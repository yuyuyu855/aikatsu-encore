# ローカル開発・操作ガイド

## 必要なもの

- Node.js 22.13.0以上。今回の実行環境は24.19.0。
- pnpm 11.19.0。`package.json` の `packageManager` に固定。
- IndexedDBに対応したブラウザ。開発サーバーを起動するPC上で操作する。

外部API、ログイン情報、クラウドアカウント、環境変数は不要です。フォント・装飾を含めアプリ実行時の外部CDNには依存しません。初回の依存インストールと画像取得にはネット接続が必要です。

pnpmがない場合は、Node.jsのインストール後に以下で用意できます。

```sh
npm install --global pnpm@11.19.0
```

Corepackを利用する環境では、管理者が指定する導入方法でも構いません。今回の検証は既に導入されたpnpmを用いており、Corepackの導入手順は検証していません。

## 起動と検証

クローンしたディレクトリへ移動し、リポジトリのルートで実行します。この作業環境での場所は `/workspace/aikatsu-encore` ですが、PC上では自分のクローン先を使ってください。以下のコマンドはmacOS／Linuxのシェル、WindowsのPowerShell／コマンドプロンプトで共通です。

```sh
pnpm install --frozen-lockfile
pnpm catalog:fetch
pnpm dev
```

`catalog:fetch` は公式画像のmanifestに従って取得し、既存ファイルもhash・形式・寸法等を検証します。画像はGitに含まれないため、初回のクローンではこの準備が必要です。公式へ接続できない時は取得処理が失敗しますが、カタログや所持データは変更せず、画像なしで `pnpm dev` を起動できます。詳しい取得・更新は [カタログ運用](catalog-operations.md) を参照してください。

PCのブラウザで `http://127.0.0.1:5173` を開きます。開発サーバーは127.0.0.1にのみ待ち受けます。5173番が使用中の場合は起動が失敗するため、そのポートを使っている開発サーバーを終了してから再実行してください。終了は `Ctrl+C` です。

```sh
pnpm typecheck
pnpm test
pnpm catalog:validate
pnpm build
pnpm test:e2e
```

`typecheck` はweb・domain・catalog、`test` はdomainの数量・バックアップ規則、catalogの参照・ID保持と取得parser、`catalog:validate` はメタデータと画像キャッシュの整合、`build` は型検証とwebの本番ビルドを行います。生成物は `apps/web/dist` に置かれます。公開や配信は行いません。

`test:e2e` はPlaywrightで検索・数量操作・保存・復元・保存失敗・小画面を検証します。Linuxで `/usr/bin/chromium` が存在すればそれを利用し、その他は次の準備が必要です。

```sh
pnpm exec playwright install chromium
```

Linuxでブラウザのシステム依存が足りない場合はPlaywrightのエラーに従って必要な依存を導入してください。システム依存の導入方法はOSごとに異なります。テストは自動で開発サーバーを起動します。先に手動の `pnpm dev` を終了してください。

## 収録範囲と操作

公式サイトの公開一覧を `packages/catalog` のカードJSONと弾別manifestに収録します。件数は固定せず、現在のmanifestのカードID集合から表示します。画面上部で「全公開カード」または弾・プロモを選択し、対象件数・出典URL・取得日を確認できます。取得範囲と具体的な更新手順は [カタログ運用](catalog-operations.md) に記載します。

公式HTMLには画像だけが掲載され、名称などの項目が存在しない場合があります。画像の読み取りで補完した情報は出典と区別して記録し、未確認の名称は「名称未確認」と表示します。番号や名前を推測で埋めません。画像から名称を確認できても、QRとカード番号の対応を検証したことにはなりません。

画像は `apps/web/public/cards` のGit管理外キャッシュから表示します。未取得・読み込み失敗時はカード番号を代わりに表示し、所持・譲求の操作は続けられます。画像をクリックするとローカルの画像ファイルを開き、裏面が収録されていれば「裏面を見る」で切り替えられます。公式への自動取得はページ閲覧時には行いません。

「カード」で名前・番号の検索、所持／未所持／譲れる／欲しいの絞り込みができます。レアリティ・パーツの選択は確認済みデータが存在する場合に表示します。表示は番号順です。所持枚数と譲れる枚数は別に増減し、欲しい状態は所持と独立して指定できます。複数枚持っていても譲れる枚数は自動で増えません。

所持を減らすと譲れる枚数を下回る場合、変更後の両方の値を示す確認画面が開きます。「調整して保存」を選ぶまで値は変更せず、「取消」では変更しません。所持は0以上の安全な整数、譲れる枚数は0以上かつ所持枚数以下です。

「所持種類」は所持が1枚以上のカードの種類数、「総所持枚数」は重複を含めた枚数です。種類率の分母は選択中の収録範囲の全カードID数です。検索・所持状態・レアリティ・パーツで絞っても分母は変えません。部分収録はその範囲と明示します。「譲・求」は自分の欲しいカード・譲れるカードを整理する画面で、他の人には公開されません。

## 保存とバックアップ

IndexedDBの `aikatsu-encore-local` データベース、`state` ストア、`inventory` キーに全登録カードの状態を一つのスナップショットとして保存します。初回の読み込みが完了するまで編集できません。保存トランザクションが成功した後で画面に反映し、失敗時は元の表示を保ってエラーを示します。

通常のカタログ追加では、全過去IDを含む登録簿に対して在庫を読み込み、既存の `owned`・`offered`・`wanted` を維持して新カードだけ0で追加します。弾の切り替えで保存状態は変更しません。旧サンプルの `e1-01`・`e1-02` も同じIDを使います。掲載終了カードのIDと在庫も登録簿に残します。

同じ保存先を複数タブで同時編集しないでください。タブ間同期や変更競合の処理は未実装です。

「バックアップ」→「JSONをダウンロード」で全登録カードのデータを保存します。表示中の弾・検索・絞り込みはバックアップ対象に影響しません。保存したファイルを、別の端末では「JSONファイルを選択」から読み込めます。ファイル全件の検証後に、所持種類・総所持枚数・譲れる枚数・欲しい種類数をプレビューします。「置き換えて復元」で現在の全データを置き換え、「取消」で保持します。ファイルに含まれない収録カードは未所持・譲0枚・欲しい未選択になります。

形式は従来と同じ `schemaVersion: 1` と `inventory` 配列で、2件だけの旧バックアップも読み込めます。通常のカタログ追加とは異なり、明示確認した復元は全置換なので、ファイルにない新カードも0になります。未対応バージョン、不正な数量、重複したカードID、未知のカードID、不正JSONなどが一件でもあれば、全体を拒否して書き込みません。未知IDが含まれる場合は新しいカタログへのアプリ更新を確認し、黙って捨てたりresetしたりしません。復元は一つのトランザクションで行い、途中で失敗した場合も元のデータを保持します。

```json
{
  "schemaVersion": 1,
  "inventory": [
    { "cardId": "e1-01", "owned": 2, "offered": 1, "wanted": true },
    { "cardId": "e1-02", "owned": 0, "offered": 0, "wanted": false }
  ]
}
```

保存先はブラウザ・端末・オリジンごとに異なります。たとえば `localhost:5173` と `127.0.0.1:5173`、5173番と別のポートは別データです。プライベートブラウズやブラウザデータの消去では失われることがあるため、JSONを別の場所へ保管してください。

このテスト版はPWAやオフライン起動を保証するものではありません。サービスワーカー、QR読取、履歴、友人との共有・同期、クラウド保存は未実装です。

## 今回の検証結果

Node.js 24.19.0 / pnpm 11.19.0、LinuxのChromiumで、型検証・本番ビルドとdomain／catalog／取得CLIの合計48テストが成功しました。Playwrightは12件すべて成功し、skipはありません。

ブラウザ操作で旧2件DBの読み込みと旧v1バックアップ復元、全107件を含むバックアップ、弾切替・検索・絞り込み後も対象弾の分母と保存内容を保つこと、無効な復元と保存中断時の元データ保持を確認しました。レアリティ・パーツ・AP、ローカル表裏画像・横向き画像、未取得画像の代替表示、375pxのカード・バックアップ画面で横にはみ出さないことも確認しています。デスクトップ・375px画面を画像でレビューしました。

Windows／macOSでの実行、Safari／Firefox、スマートフォン実機の操作は未検証です。
