# ローカル開発・操作ガイド

## 必要なもの

- Node.js 22.13.0以上。今回の実行環境は24.19.0。
- pnpm 11.19.0。`package.json` の `packageManager` に固定。
- IndexedDBに対応したブラウザ。開発サーバーを起動するPC上で操作する。

外部API、ログイン情報、クラウドアカウント、環境変数は不要です。フォント・装飾を含めアプリ実行時の外部CDNには依存しません。初回の依存インストールにはネット接続が必要です。

pnpmがない場合は、Node.jsのインストール後に以下で用意できます。

```sh
npm install --global pnpm@11.19.0
```

Corepackを利用する環境では、管理者が指定する導入方法でも構いません。今回の検証は既に導入されたpnpmを用いており、Corepackの導入手順は検証していません。

## 起動と検証

クローンしたディレクトリへ移動し、リポジトリのルートで実行します。この作業環境での場所は `/workspace/aikatsu-encore` ですが、PC上では自分のクローン先を使ってください。以下のコマンドはmacOS／Linuxのシェル、WindowsのPowerShell／コマンドプロンプトで共通です。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

PCのブラウザで `http://127.0.0.1:5173` を開きます。開発サーバーは127.0.0.1にのみ待ち受けます。5173番が使用中の場合は起動が失敗するため、そのポートを使っている開発サーバーを終了してから再実行してください。終了は `Ctrl+C` です。

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

`typecheck` はwebとdomain、`test` はdomainの数量・バックアップ規則、`build` は型検証とwebの本番ビルドを行います。生成物は `apps/web/dist` に置かれます。公開や配信は行いません。

`test:e2e` はPlaywrightで検索・数量操作・保存・復元・保存失敗・小画面を検証します。Linuxで `/usr/bin/chromium` が存在すればそれを利用し、その他は次の準備が必要です。

```sh
pnpm exec playwright install chromium
```

Linuxでブラウザのシステム依存が足りない場合はPlaywrightのエラーに従って必要な依存を導入してください。システム依存の導入方法はOSごとに異なります。テストは自動で開発サーバーを起動します。先に手動の `pnpm dev` を終了してください。

## 収録範囲と操作

収録するのは提供画像で番号・名前・レアリティを確認した以下の2種です。公式照合や実物コードの検証は行っていません。参考画像の「85種」を公式の全件数とは扱わず、全件カタログは未収録です。

| 番号 | レアリティ | 名前 | 内部ID |
| --- | --- | --- | --- |
| E1-01 | PR | オーロラキスキャミソール | e1-01 |
| E1-02 | PR | オーロラキスドレープスカート | e1-02 |

「カード」で名前・番号の検索、所持／未所持／譲れる／欲しいの絞り込みができます。表示は番号順です。所持枚数と譲れる枚数は別に増減し、欲しい状態は所持と独立して指定できます。複数枚持っていても譲れる枚数は自動で増えません。

所持を減らすと譲れる枚数を下回る場合、変更後の両方の値を示す確認画面が開きます。「調整して保存」を選ぶまで値は変更せず、「取消」では変更しません。所持は0以上の安全な整数、譲れる枚数は0以上かつ所持枚数以下です。

「所持種類」は所持が1枚以上のカードの種類数、「総所持枚数」は重複を含めた枚数です。種類率の分母はこのサンプル2種だけです。「譲・求」は自分の欲しいカード・譲れるカードを整理する画面で、他の人には公開されません。

## 保存とバックアップ

IndexedDBの `aikatsu-encore-local` データベースに全カードの状態を一つのスナップショットとして保存します。初回の読み込みが完了するまで編集できません。保存トランザクションが成功した後で画面に反映し、失敗時は元の表示を保ってエラーを示します。

同じ保存先を複数タブで同時編集しないでください。タブ間同期や変更競合の処理は未実装です。

「バックアップ」→「JSONをダウンロード」で保存したファイルを、別の端末では「JSONファイルを選択」から読み込めます。ファイル全件の検証後に、所持種類・総所持枚数・譲れる枚数・欲しい種類数をプレビューします。「置き換えて復元」で現在の全データを置き換え、「取消」で保持します。ファイルに含まれない収録カードは未所持・譲0枚・欲しい未選択になります。

形式は `schemaVersion: 1` と `inventory` 配列です。未対応バージョン、不正な数量、重複したカードID、未知のカードID、不正JSONなどが一件でもあれば、全体を拒否して書き込みません。復元は一つのトランザクションで行い、途中で失敗した場合も元のデータを保持します。

```json
{
  "schemaVersion": 1,
  "inventory": [
    { "cardId": "e1-01", "owned": 2, "offered": 1, "wanted": true },
    { "cardId": "e1-02", "owned": 0, "offered": 0, "wanted": false }
  ]
}
```

保存先はブラウザ・端末・オリジンごとに異なります。たとえば `localhost:5173` と `127.0.0.1:5173`、5173番と別のポートは別データです。プライベートブラウズやブラウザデータの消去では失われることがあるため、JSONを別の場所へ保管してください。

このテスト版はPWAやオフライン起動を保証するものではありません。サービスワーカー、QR読取、履歴、友人との共有・同期、クラウド保存は未実装です。

## 今回の検証結果

Node.js 24.19.0 / pnpm 11.19.0の環境で、固定lockfileによる依存インストール、web/domainの型検証、本番ビルド、domain 36テスト、Chromiumのブラウザ操作7テストが成功しました。ブラウザ操作では再読み込み後の保存、JSON復元の確認・取消、不正ファイルの全体拒否、IndexedDB書き込み中断時の元データ保持、375pxのカード・バックアップ画面で横にはみ出さないことを確認しています。デスクトップ・375px画面も画像で確認しました。

Windows／macOSでの実行、Safari／Firefox、スマートフォン実機の操作は未検証です。
