# 追加スクリーンショットからの要件定義

2026-10-06の追加依頼。提供された4画面を機能の根拠に、現在のReact／Vite・端末内保存アプリへ追加する。固有ロゴや画面の素材はコピーせず、既存の独自配色・タイポグラフィと操作名を維持する。画像付きのローカル版と、公式カード画像を含まない静的テスト公開版の両方で使えることを条件とする。

## 対象と受入条件

| 画面 | 実装する操作・表示 | 受入条件 |
| --- | --- | --- |
| カード | 2列のカードグリッド。番号・名前・メタデータ、所持増減、譲れる枚数増減、欲しい状態。縦横画像を同じ大きさの画像領域へcontain表示 | 375pxでも2列、名前は折り返し、数量と欲しいを操作できる。縦横画像で枠の高さが変わらず、切り抜きや縦横比の変形がない。画像なしでも全操作可能 |
| コーデ | 検証した組合せ単位の完成状態・不足パーツ・不足のみ表示。選択弾と連動 | 必須パーツを各1枚以上持つ時だけ完成。譲・求では完成判定しない。任意パーツは必須の分母に混ぜない。別弾の必須カードも全登録簿で判定し、推測だけの名前一致ではグループ化しない |
| 譲・求 | 選択収録範囲の求／譲リスト、文章コピー、各区分のPNGプレビュー・ページ選択・共有／ダウンロード | 求と譲を混ぜず、譲だけ枚数を明示。12件／ページ、13件以上で次ページへ移動でき、黙って切り捨てない。PNGは実ファイルでプレビューと一致。画像を含まない公開版のPNGもメタデータだけで生成可能 |
| 店舗 | 確認済み店舗の検索・都道府県・お気に入り・地図／経路リンク、利用者が記録する筐体台数とメモ | 公式出典・確認時期を示す。名称／住所検索と都道府県条件が両方効く。お気に入り・台数・メモは端末内へ保存。未記録台数は「未確認」で0台と区別し、利用者メモを公式情報やリアルタイム稼働状況と扱わない |
| 履歴 | 在庫・譲求・店舗記録・復元の操作日時と変更前後、直近操作を元に戻す | 保存成功した操作だけを記録。最新の変更対象が記録後の値と一致する時だけUndo可能。Undoは原子的に保存して記録し、復元・取込履歴・Undo操作自体は取り消せない。初回50件とさらに表示で長い履歴に対応 |
| バックアップ | 在庫・履歴・店舗設定の全バックアップ、旧v1互換、全件検証と確認後の復元 | 新規書出しはschemaVersion 2。v1在庫ファイルも読める。無効な履歴・設定が一件でもあれば全体拒否。v1復元では現履歴・店舗設定を保持。v2復元では検証した全内容を反映し、取込履歴のIDを再識別する |

## 共通の保存・公開境界

全登録カードのID・DB名 `aikatsu-encore-local`・`state` ストア・`inventory` キーを維持する。表示弾や絞り込みで保存状態を投影・削除しない。新機能の操作はrevisionを伴う一つの保存入口へ集約し、現在値の確認と変更・履歴の追加を同じトランザクションで確定する。失敗時は在庫・設定・履歴をすべて保持し、保存成功と表示しない。

同じ状態への保存は履歴を増やさない。新しい保存形式へ読み込んでも旧カードの所持・譲・求を保つ。未知のカードIDは黙って破棄せず停止し、店舗設定の既存IDはカタログの表示対象変更で消さない。取込履歴は元のIDを補足として保持し、現履歴とID衝突させず、取込履歴そのものをUndoの対象にしない。

静的公開版は現在のカード画像非掲載設定を維持する。カード画像・共有PNG・コーデ画像から公式画像へ自動でアクセスしない。共有は利用者のコピー・ファイルダウンロード・ブラウザの共有操作によるもので、アカウント・友人同期・交換予約・在庫の自動移動は追加しない。地図と経路は外部リンクを開く。地図SDK・位置情報の自動取得・有料APIは使わない。

## コンポーネントと担当境界

| 担当 | 所有するファイル・責務 |
| --- | --- |
| UI統合 | `App.tsx`、`components/` の共通UI・CardsPage・HistoryPage、共通 `styles.css`、本要件と実装計画。Appが読み込み・操作通知・確認ダイアログ・ページ統合を担当 |
| 保存基盤 | domainの状態・イベント・バックアップ検証、webの保存層。revision確認、在庫／設定／履歴の原子的保存・Undo・旧形式互換 |
| コーデ | `features/coordinates/` の検証済みグループ情報とCoordinateView、専用CSS。全カードと全在庫を受け取り、選択弾だけで表示を絞る |
| 譲求出力 | `features/exchange/` のExchangePanel・コピー／PNG出力・専用CSS。選択範囲のカードと全在庫を読取専用で受け取る |
| 店舗 | `features/stores/` の公式由来店舗データ・StoresScreen・専用CSS。設定はprops、保存はAppへの非同期callbackで行う |
| QA | `apps/web/e2e/` と既存のテスト設定。既存機能・公開版の回帰と新機能の機能確認 |

各featureはIndexedDBへ直接書き込まず、App経由のcallbackを使う。新しい画面は専用ファイルへ分け、複数担当がAppを同時編集しない。共通CardArtworkは公開設定とローカル画像URLを一か所で扱う。

## 実装順と検証

1. 要件・データ出典・型と担当境界を確認する。
2. 保存基盤の状態・履歴・設定・v1／v2検証を整備する。並行して画面を独立コンポーネントへ分割する。
3. カードグリッド、コーデ、譲求出力、店舗、履歴を型の契約に合わせて実装・統合する。
4. 数量制約・CAS競合・保存失敗・最新Undo・不正v2復元・旧v1互換をテストする。
5. ブラウザで2列表示、コーデ不足、13件以上のPNG、コピー／共有の代替、店舗記録とUndo、再読み込みを確認する。公開版の生成物と通信で公式画像非掲載を確認する。
6. 型検証・ローカル／公開版ビルド・関連テスト、375pxとデスクトップの画像レビューを完了し、実績と未検証事項を記録する。

QR、コード読取、アカウント、クラウド同期、オフライン起動保証、リアルタイム店舗照会は今回の対象に含めない。検証していないブラウザ共有APIは成功を断定せず、PNGダウンロードを利用できるようにする。

## 実装・検証結果（2026-10-06）

6画面の統合と上記の保存・復元を実装した。型検証、ローカル／公開版ビルド、domain・catalog・保存層・Nodeの合計95テストが成功した。ブラウザ検証はローカル22件と公開版5件がすべて成功し、skipは0件。375pxのカード2列、コーデ、店舗、履歴、交換画像プレビューと生成PNGを画像でレビューした。公開成果物は3ファイル、公式画像バイナリと公式画像への自動通信はともに0件。

PNG生成・保存は実ブラウザで確認した。共有APIの対応・成功・中止・非対応分岐は模擬テストで確認し、OSの共有画面とスマートフォン実機は未検証とする。詳細な実行手順と検証範囲は [local-development.md](local-development.md) を参照する。
