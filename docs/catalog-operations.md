# 弾の追加とカタログ更新の運用

公式サイトで現在公開されている一覧を取得し、出典付きのカードJSONと弾別manifestで管理します。2026-10-05の取得では、第1弾85件とプロモーションカード22件、計107件を確認しました。各カードの表・裏を合わせて214画像を取得し、WebPのデコード、SHA-256、バイト数、画像寸法を検証しました。この件数は今回の取得結果であり、将来の固定期待値にはしません。

公開中の収録範囲は公式の弾選択肢で確認します。第2弾以降のIDを連番と推測せず、新弾の公式URLを確認して追加します。今回のHTMLの掲載件数と解析したカード件数は一致しています。ページを開くたびの公式取得、常時スクレイピング、cronは使いません。

公式HTMLはカード番号・画像識別子・表裏の画像URLを掲載していますが、名称・パーツ・ブランドなどのフィールドはありません。これらは未確認のまま推測で埋めず、カード画像から確認できた情報を別の補完情報として記録します。今回の画像確認では全107件の名称・パーツ・APと54件のブランドを確認しました。残る53件は印刷ブランド表示がなく、未設定を維持します。今後、未確認名称がある場合は画面で「名称未確認」と表示します。公式画像にある表記とHTML由来のデータは出典を区別します。QRの実形式・カード番号との対応は未検証です。

元HTMLの出典・取得日時・hashと、画像の取得URL・hash・寸法・バイト数をカタログのprovenanceに残します。画像に記載された数値や名前が取得時点と異なる可能性を、根拠なく補正しません。

## データと画像の置き場所

`packages/catalog/data/cards.json` が全過去IDの登録簿、`manifest.json` が弾ごとの表示対象、`images.json` が取得URL・hash・寸法、`labels.json` が画像から確認した補完情報を持ち、`apps/web` が読み込みます。公式の公開状態（sourceStatus）とアプリの収録状態（coverageStatus）を区別し、稼働開始日から推論しません。カタログの版・取得日・公式URLと収録件数を画面に表示します。

カード画像は `apps/web/public/cards` のGit管理外ローカルキャッシュです。公式サイトは転載禁止を掲示しているため、画像ファイルをこのリポジトリへコミットせず、取得URL・hash等のmanifestと再取得ツールを管理します。画像・掲載データの出典は公式サイトで、自作素材として扱いません。アプリ閲覧時はキャッシュだけを参照し、画像がない場合も番号とメタデータで操作できます。キャッシュがないままビルドしても画像は生成物へ同梱されません。

カードの内部IDは不変とし、表示番号・名前・レアリティ・画像ファイル名と分離します。初期サンプルの `e1-01`・`e1-02` は維持しています。表記訂正や画像更新ではIDを作り直しません。同じ衣装の再録を、未確認のメタデータだけで同一カードと扱いません。

## 画像キャッシュの取得・検証

リポジトリのルートで実行します。取得ツールはcommit済みの画像manifestだけを対象にし、公式URLの内容が期待するhash・形式・寸法・バイト数と一致することを確認してからキャッシュへ置きます。取得済みで一致する画像は再利用します。

```sh
pnpm install --frozen-lockfile
pnpm catalog:fetch
pnpm catalog:validate
```

`catalog:validate` はカタログの参照・件数と全画像キャッシュを検証します。カタログの構造だけを確認する時は `pnpm catalog:validate --metadata-only` を使えます。このオプションでは画像ファイルを検証しません。キャッシュがない場合はエラーになります。取得失敗や内容の不一致があれば処理を停止し、カタログJSONや利用者のDBを書き換えません。hashやTLS検証を無効にして通しません。取得に成功したキャッシュはGit管理外に残り、再実行で確認して再利用できます。

## 新しい一覧をstagingへ取得

新弾の公式URLと、不変の内部set IDを確認して実行します。以下は現在の第1弾を再確認する例です。

```sh
pnpm catalog:stage --url "https://dcd.aikatsu.com/encore/cardlist/?search=true&series=629001&display=3&sort=1" --set-id encore-1 --label "1弾"
```

公式HTMLを自分で保存した場合は `--html cardlist.html` を追加できます。`--url` は出典と掲載画像の参照検証に必要です。

```sh
pnpm catalog:stage --url "https://dcd.aikatsu.com/encore/cardlist/?search=true&series=629001&display=3&sort=1" --set-id encore-1 --label "1弾" --html cardlist.html
```

出力はGit管理外の `catalog-staging/encore-1.candidate.json` です。`--out` で出力先を指定できます。件数・source hash・追加・訂正・掲載消失の差分を含み、現在のカタログやIndexedDBへは反映しません。このツールは候補一覧の取得までで、候補画像の取得・検証とカタログへの昇格は自動化していません。

管理者と実装担当は候補と画像を検証し、全過去IDを保持した `cards.json`、弾の表示対象を持つ `manifest.json`、取得根拠を持つ `images.json`、必要な名称補完を更新します。既存IDを作り直さず、掲載消失を自動削除しません。差分レビューと関連テストの後、通常のcommit／pushで配布します。画像ファイルをcommit対象に含めません。

## 利用者の更新手順

更新前に「バックアップ」でJSONを保存し、アプリの全タブと開発サーバーを終了してください。自分のPCのリポジトリルートで実行します。macOS／Linuxのシェル、WindowsのPowerShell／コマンドプロンプトで共通です。

```sh
git pull --ff-only
pnpm install --frozen-lockfile
pnpm catalog:fetch
pnpm catalog:validate
pnpm build
pnpm dev
```

同じブラウザ・同じ `http://127.0.0.1:5173` を使って再読み込みします。更新のためにホスト名やポートを変えると、別のIndexedDB保存先になります。画像キャッシュの準備は取得ツールの手順を用い、取得後に本番ビルドへ反映する場合は再度 `pnpm build` を実行します。これらは公開・配信コマンドではありません。

## 所持データを消さない更新

カタログと利用者の在庫は別のデータです。保存層は選択弾の小さい一覧ではなく、掲載終了カードを含む全過去IDの登録簿で検証します。通常の更新では既存の `owned`・`offered`・`wanted` を維持し、新カードだけ0で補います。検索・絞り込み・弾の切り替えで保存内容は変更しません。

掲載消失はIDの削除ではなく `retired` と通常一覧の非表示で扱い、在庫とバックアップに残します。名称や画像の訂正でもIDと在庫を保持します。未知IDが保存データに含まれる場合は安全に停止し、新しいカタログへのアプリ更新を案内します。無言で捨てたりresetしたりしません。

DB名 `aikatsu-encore-local`、STORE `state`、key `inventory` を維持しています。2件だけの旧v1バックアップも読み込めます。履歴・店舗設定を加えた新しい書出しはschemaVersion 2ですが、カタログ追加そのものでは形式を変更しません。v1復元時は現在の履歴・店舗設定を保持します。

通常のカタログ更新と、利用者が確認したJSONの全置換復元は別操作です。旧バックアップの復元ではファイルにない新カードも0になります。確認画面に全登録カード数と所持・譲・求の概要を示し、確認までDBを書き換えません。表示中の弾にかかわらず、バックアップ・復元は全登録IDが対象です。

## 集計と更新の確認

種類数は選択中の収録範囲で `owned > 0` のユニークID数、分母はその範囲の全収録ID数です。検索・所持状態・レアリティ・パーツで絞っても分母は変わりません。全公開カードでは同じIDを二重計上しません。partialの収録範囲で100%になっても、公式の全カードを集めた意味にはしません。

新しい取得候補は必須項目・重複・番号衝突・画像hash・件数差分を確認してから反映します。空、欠落、掲載消失や想定外の大減少がある候補を、現在のカタログへ自動反映しません。sourceの差分と根拠をレビューし、ユーザーの在庫は変更せずカタログの版を更新します。

検証には以下を含めます。架空の弾・カードはテスト専用fixtureとし、実カタログへ混ぜません。

- 旧2件のDBと旧v1バックアップを読み、既存の所持・譲・求を維持する。
- 弾の切り替え、検索、絞り込みで保存内容を変えず、別弾の在庫もバックアップする。
- 掲載終了IDと表記訂正後の在庫を保持し、未知IDは全件拒否する。
- 表裏のローカル画像と横向きカード、未取得画像の代替表示を確認する。
- 型検証・ビルド・数量／復元テストと小画面のブラウザ操作を確認する。
